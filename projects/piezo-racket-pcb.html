Eleven piezo channels inside a table-tennis handle

Where a ball lands on the blade, and how hard, shows up as vibration in the blade. Cabled sensors may change how a racket feels, so every part of this recorder has to fit inside the handle: charge amplifiers for 11 film electrodes, two synchronised ADCs, an IMU, Wi-Fi and a charger, on an 18 × 75 mm, 6-layer board. The design is finished and checked; the board has not been built, so nothing below is a measurement.

Mu-Hua Wang · advisor: Jing-Chen Hong (Institute of Electrical and Control Engineering, NYCU)

Ten strips on two films should place a hit without a sensor at every spot

The forehand film carries five horizontal strips (R1–R5) and the backhand film five vertical ones (C1–C5). A ball that lands where an R strip and a C strip cross should excite that pair more than the rest, so ten channels can name a grid of places. Checking the drawing for this page turned up a flaw: the label says 25 crossings, but at the rounded corners three pairs (R1×C5, R5×C1, R5×C5) do not overlap at all, so only 22 of the 25 pairs actually cross. Click anywhere on the blade to see which pair would answer.

A simulation found a mistake 50 times the noise floor before anything was ordered

Without hardware, the only way to find mistakes is to check the design in ways that do not share its assumptions. Two loop-back paths (an LED timing signal and an IMU interrupt fed back into spare ADC channels) were pushing a small direct current into the reference voltage that all eleven amplifiers share.

The board-level simulation showed an error of about 1.2 mV at the differential input (with the film shield in place), 50× the ADC noise. Nothing in the rule checks flags this, because the circuit is wired exactly as drawn. The LED loop-back resistors were reconnected to ground and the IMU loop-back resistor was left unfitted; the copper change touched only the ground and reference nets.

The checker that reads the factory files was itself broken on purpose

Under the project’s rule set, KiCad’s design-rule and schematic-parity checks report 0 violations, 0 unconnected items and 0 mismatches. But those checks run inside the same tool that drew the board. So a separate program reads only the files the factory receives (copper, solder-mask and outline layers and the drill file), rebuilds which pad connects to which from copper and drill, and compares that with the schematic: 150 nets and 701 pads, 0 opens, 0 shorts. A checker that never fails proves little, so it was given eight copies of the board, each damaged in one way. Its first version missed one of them, a gap only slightly too narrow, because it had no pass/fail threshold; it was rewritten and then caught all eight.

The goals and the trade-offs

I decided what the board must do and every trade-off that followed: all electronics inside the handle, both players’ rackets recorded, a spare ADC channel for an LED timing loop-back so the data can be lined up with a camera, a single ground, a longer board and six layers instead of four. The schematic, placement, routing, simulations and checks are generated by 117 scripts (12,959 non-blank lines), so the whole design can be rebuilt and re-checked from source. My part of the checking was to ask for the kind of pre-fabrication review a board house would expect, to ask for independent ways to test the answers, and to decide which results to trust.

Where this stops

Scope: design, simulation and file checks only. No board has been made, powered or tested, and no hit has been recorded, so the film read-out above is the intended design, not a result. The simulations use estimated film properties. In the thermal model the board overheats if charged with Wi-Fi on; the design relies on a firmware rule to prevent it. 32 kS/s per channel needs a driver that does not exist yet. The emission figure covers board traces only. ERC still lists 3 warnings of one kind (bidirectional pins tied to a power-output flag on the IMU).
