# PREREG — 重新最佳化是否就是「重新分配」的來源 (r423)

**Registered:** 2026-08-26,在對任何低劑量凍結 cell 讀取關節角度之前。無新最佳化,不耗授權。

---

## 1. 主張

`SPANNING_RESULT_r421.json` 量到:在重新最佳化的系統裡,單肌肉痙攣在**三個關節都造成分離**,
包含該肌肉根本不跨過的髖;且**跨膝的腓腸肌移動膝關節比不跨膝的比目魚肌少三倍半**。

> **這個「重新分配」是最佳化器造成的,不是病灶的力學後果。
> 若禁止重新最佳化,同一個病灶的效應應該退回它所跨越的關節。**

## 2. 為什麼現在才能測

此對比一直做不成,因為凍結的臂全部跌倒:`FROZEN_MECHANISM_r410` 0/6(KV 0.050),
`RECON_LOWDOSE_r420` 在 0.005–0.040 也沒有任何劑量讓兩隻單肌肉臂同時到 4/6。

**r421 找到了兩個重新最佳化下 6/6 過 Gate G 的劑量:KV 0.0125 與 0.025。**
把**同樣的劑量**拿去凍結重播,即可得到兩側劑量相同的配對比較。
凍結側是否過 Gate G 為待測事實,不是假設。

## 3. 材料

**凍結側(本輪新建)**:以各 seed 的 `R151C` 最佳解為凍結控制器,注入
`GASONLY` / `SOLONLY` / `BOTH`,KV ∈ {0.0125, 0.025},seeds 101–106 = **36 cell**,
`sconecmd -e` 重播,寫在 staging 樹內,不碰 SCONE results。

**重新最佳化側(已存在)**:`SPANNING_RESULT_r421.json` 的同名同劑量臂,不重新計算。

**對照**:凍結 `R410NONE`(已存在,6/6 過 Gate G,撐滿 20 秒)與重新最佳化 `R151C`。

## 4. 終點

與 r421 完全相同,不得更改:`KNEE_ic`、`ANKLE_st`、`HIP_ic`,語料庫窗口慣例不變。
各臂相對於**其自身側的對照**取位移(凍結臂減 `R410NONE`,重新最佳化臂減 `R151C`),
以免把兩側的基線差混進來。

## 5. 註冊的預測

判讀劑量為**凍結側兩隻單肌肉臂都達到 ≥ 4/6 Gate G 的最高階**。
若凍結側在兩個劑量都拿不到 4/6,本註冊回報 **UNINFORMATIVE**,且**不得**改用未過 Gate G 的
凍結讀數補救 —— 那正是 `CORRECTION_r416` 退役 r410 的理由。

**P1 — 髖(關鍵預測)。** 凍結側 `GASONLY` 與 `SOLONLY` 的 `HIP_ic` **重疊**。
兩條肌肉都不跨髖;若禁止重新最佳化後髖仍然分開,則重新分配不是最佳化器造成的,本主張失敗。

**P2 — 膝的方向回正。** 凍結側 `|GASONLY 的膝位移|` **大於** `|SOLONLY 的膝位移|`。
重新最佳化側是 1.09 對 3.84(跨膝的那條反而較小);若凍結側仍然反向,本主張失敗。

**P3 — 重新分配量。** 定義 `SPREAD = |膝位移| + |踝位移| + |髖位移|` 中**非跨越關節**所佔比例
(`GASONLY` 的非跨越關節為髖;`SOLONLY` 為膝與髖)。凍結側的該比例**低於**重新最佳化側。

**P4 — 踝。** 兩側的 `ANKLE_st` 都應顯示位移(兩條肌肉都跨踝),此為健全性檢查;
若凍結側踝完全不動,表示凍結注入無效,整輪作廢。

## 6. 事先註冊的控制

- **時長控制**(r417 程序)對 P1、P2 強制執行,超過 50% 判 CONFOUNDED。
- **兩側的 Gate-G 通過數必須並列報告。** 若凍結側僅勉強達 4/6 而重新最佳化側為 6/6,
  該不對稱須寫入判決,不得忽略。
- **擺盪期時長須並列報告**(`SWINGMATCHED_r419` 的教訓)。

## 7. 本註冊不能建立什麼

1. 凍結控制器不是病人。它移除的不只是「重新最佳化」,也移除了任何即時的反射性適應。
   本註冊測的是「最佳化器」這個特定機制,不是「所有適應」。
2. 六個凍結控制器來自同一次控制最佳化,不是六個獨立的神經系統。
3. 與 6.3919° 頭條無關 —— 頭條是痙攣對無力,本輪是兩條痙攣肌互比。
4. 若凍結側大量跌倒,結果只適用於「勉強能走」的狀態,不可外推。

## 8. 禁止事項

不得更改劑量、窗口、終點或門檻。不得在看到結果後新增劑量。
不得使用未過 Gate G 的凍結讀數。註冊正文一律不修改(見 `DEFECT_r417_hash_break.md`)。
若出現 §5 沒有類別的結果,記為 REGISTRATION DESIGN DEFECT,該預測按字面判為失敗。
**P1–P3 已明確寫出各自的失敗條件;失敗即記為失敗,不得改寫成「部分支持」。**
